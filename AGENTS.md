# Project rules
- Mature-content discovery uses one shared read-boundary classifier and includes genre metadata on projected anime joins; this is a display preference, never an access-control rule.
- Data Saver overrides the main player's quality lock without replacing saved preferences; compact settings reuse a scoped tokenized glass surface.
- Cache clearing deletes only the named image caches and signed-in watch history without a document reload; catalogue metadata, favorites, offline videos and credentials survive.
- History-reset write suppression ends on new navigation, not on cleanup dismissal, so stale players stay paused while new sessions can save progress.
- Both Shadow link sharing controls use one shared visibility predicate to prevent account allowlists from drifting; it does not grant administrator or playback bypass privileges.
- Download audio discovery uses a lazy, bounded MP4 metadata reader only when native track metadata is unavailable; never fetch the entire video to populate the selector.
- Download metadata probes have bounded deadlines and never gate confirmation indefinitely, because CDN metadata can hang or be unavailable.
- Copied embed players store exact native-media checkpoints by resolved episode ID through a shared resume hook; do not fabricate third-party iframe positions.
- Anime poster cards render through the shared PosterCard so badges, artwork sizing and fallbacks stay consistent across rows, grids and platform pages.
- Discovery, platform and continue-watching rows reuse catalogue glass tokens and native snap scrolling to avoid animation-loop and per-card blur overhead.
- Main hero: phones show uncropped 16:9 art with copy below, larger screens full-bleed with overlaid copy, visibility-gated autoplay; resume cards keep edge-to-edge aspect-ratio art separate from text.
- Anime details retain shared EpisodeGrid, MoreInfoDrawer, download, share and review components in an unframed layout so visual refreshes preserve their existing behavior.
- Pending Upload reuses catalogue glass and keeps presentation separate from existing role checks, queue heuristics, realtime updates and edit actions to avoid changing upload permissions during redesigns.
- Pass anime SUB classification into the shared audio selector; known stream metadata takes precedence over content-language fallback labels.
- Watch passes both SUB and Hindi-dub classification into the shared audio fallback, while detected track labels remain authoritative.
- Watch and Upload presentation reuse catalogue glass tokens, keep playback unframed, and remove per-card duplicate backdrop images without modifying upload guards or media policies.
- Account pages use unframed grids and the shared glass Button variant; hamburger and detail loader share account glass tokens with motion/performance fallbacks, keeping existing handlers.
- Settings uses a single unframed vertical section flow; catalogue listing pages share lightweight optical-edge tokens and SeeAllHeader so page refreshes preserve existing links, badges and queries.
- Welcome renders catalogue banner artwork behind its title and actions with visibility-gated rotation rather than animated ambient backdrops, keeping its first screen lightweight.
- Utility popups, navigation and footer share bounded optical-glass tokens with performance fallbacks; presentation changes retain popup queues, route exclusions, contact destinations and update state transitions.
- Login, notification and resume reuse utility glass without changing auth or history handlers; clone utility exclusions key off the resolved clone shell mode so anime-slug pages stay normal.
- Token expiry and verification surfaces reuse utility glass and TokenPerks with bounded blur and unframed sections; keep access checks, popup frequency and token action handlers independent of presentation.
- Homepage sharing uses native sharing with a copy-link fallback and direct social links, keeping the primary action independent of poster generation.
- Download confirmation pauses playback and does not automatically resume it on dismissal, so users control playback explicitly.
- Popular catalogue cards retain shared audio/content badges and native scroll snapping; animations must respect reduced motion and device performance tiers.
- All HLS server players use getHLSConfig as the single buffering/network policy, preserving native Safari playback and manual quality/server choices to prevent tuning drift.
- The page quality lock applies on every device when Data Saver is off; Data Saver caps adaptive levels and preserves saved quality choices, so the label matches actual playback.
- PIN lock gate and settings share scoped pin glass tokens; the token banner keeps its fixed 25px strip geometry so restyles never shift page layout.
- Header touch-target overrides are scoped to nav classes; PC nav links live in the hideable SideRail (lg+), keeping the header single-row on every device.
- Trending Now and Top Trending each have an admin lineup table edited in separate hero-editor modes so lists never interact; empty Trending Now hides it.
- Watch Stats uses scoped optical tokens and unframed account sections while retaining existing statistics calculations.
- Homepage Latest Series and Latest Episodes share one security-invoker catalogue RPC and a short-lived query cache to reduce duplicated requests without bypassing row permissions.
- The header hamburger is an anchored Popover built from one menuSections list and the profile dropdown renders on every device; both keep role guards and existing handlers so menu restyles never change access.

- Admin uses unframed tools with one utility-glass nav layer; upload editors share authenticated server-role checks (never session-storage codes) so admins without uploader roles can edit.
- Upload no longer uses the legacy password gate; retain server-role and database permission checks as the access authority.
- Pending preparation popups use the shared portaled Dialog so transformed sections can't trap them; homepage recommendations stay separate from Watch playback.
- Upload creation/series editing use unframed sections (no Card wrappers), one vertical form flow and scoped studio tokens; keep upload handlers and guards.
- Episode editing scopes the studio presentation to its page and embedded tools without altering shared subtitle or timestamp handlers, so other upload surfaces keep their existing behavior.
- Crunchy/MuseIN share a portaled loader whose lifetime follows real catalogue requests (no fake progress or delays).
- Platform collections share presentation-only catalogue headers/cards (portrait art, shared badges, snap rows); keep page-owned filters, queries and handlers.
- Watch party create/join/view dialogs share scoped party glass presentation; header menu party dialogs are controlled outside the hamburger sheet so closing the menu never unmounts them.
- The coarse-pointer 44px tap-target rule excludes switch, checkbox and radio roles so toggles keep their size.
- Watch party state lives in the shared watchPartySession store: only the host writes playback (host-only UPDATE), guests get a cover and reverted media events, and party sessions skip Continue Watching.
- Clone sites forbidding framing get a header-only backend check and an open-directly card; never proxy or strip frame protections.
- Progress writes use watchProgressThrottle, polls skip hidden tabs, conversion scans run daily at most, so idle tabs don't wake the database.
- Site-wide flat styling lives in src/styles/flat-design.css (loaded after index.css) as token overrides; restyle there, not per component, for consistency.
- One Watch Party menu entry; admin/upload in PC rail; Notifications is a page (shared useNotifications cache).
- Phone Watch sections (MobileWatchSections) reuse page season/episode handlers.
- getServerGroups (is_sub_only) groups DUB/SUB servers; SUB = AS+ engine, audioLocked, getServerVideoUrl.
- Detail/Watch season pickers use shared SeasonCards (pages keep their handlers); player loaders share PlayerSpinner.
- Watch comments load once per episode and sort in memory (sortComments) so sorting never reloads the player.
